做独立游戏时，美术是最容易被牺牲的一环——尤其当你用占位图的时候，很容易想「反正以后要换正式美术，先随便给它们套同一张图吧」。

这个项目一开始就是这么干的：**六种敌人共用同一张「跳尸」精灵**，只靠染色和缩放区分。

直到我为了检查它们能不能被认出来，把它们并排放在一起。结果发现两个 Boss——**尸王和旱魃——的剪影相似度是 1.00**。它们完全是同一张图。

这篇文章讲怎么把「可辨识度」这件事从主观感觉变成可量化、可自动化验证的指标，以及我在这个过程中把指标本身做错的三次。

## 为什么这是玩法问题，不是美术问题

先明确一件事：**玩家在混战里认的是轮廓，不是配色，不是细节，更不是贴图精度。**

原因很简单——他只有零点几秒做判断：

- 这个是**血尸**（死后会炸）→ 我必须**在远处**打死它
- 这个是**黑僵**（血厚慢速）→ 我可以**集中火力硬啃**
- 这个是**养尸人**（会召唤）→ 我必须**主动冲过去**点杀后排

认错的代价是直接的：贴脸打死一只血尸，然后被炸掉半条命，而玩家完全不知道自己做错了什么。**他会觉得「这游戏莫名其妙」，而不是「我犯了个错」。**

而 640x360 的逻辑分辨率下，敌人只有 16 像素高。放大到屏幕上，一个敌人大概占 40~50 个屏幕像素——这个尺寸下，配色差异几乎不可辨，**只有轮廓形状是可靠的**。

这张图就是为此专门做的一个工具，后面会讲。

## 第一步：把规则写成硬标准

「要长得不一样」这种话没法测。所以要写成一个可以被程序判断的规则：

> **共用同一张精灵的敌人，必须是在机制上可以互换的。**

「机制上可以互换」指的是：玩家面对它们该做的动作完全一样。具体到这个项目，判定条件是这些字段全部相同：

```gdscript
func _same_threat_profile(a: EnemyStats, b: EnemyStats) -> bool:
    return a.movement_mode == b.movement_mode \
        and a.summon_interval <= 0.0 and b.summon_interval <= 0.0 \
        and a.death_explosion_radius <= 0.0 and b.death_explosion_radius <= 0.0 \
        and a.attack_interval <= 0.0 and b.attack_interval <= 0.0 \
        and a.is_boss == b.is_boss \
        and a.clear_field_on_spawn == b.clear_field_on_spawn
```

（这段代码里的续行符是 GDScript 语法，用来把长条件分成几行。）

规则的效果是：**普通的"追着砍"僵尸之间可以共用轮廓**（因为玩家对它们的应对方式确实一样），但只要任意一条不同，就得长得不一样。

比如「跳尸」和「黑僵」的相似度是 0.744，**测试会跳过它们**——两者都是追人型、都没有特殊能力，共用轮廓在机制上是允许的。

## 第二步：怎么量「剪影相似度」

思路很直接：**把两张精灵的不透明像素取出来，对齐之后叠在一起，算交并比（IOU）。**

IOU 的算法是「交集 ÷ 并集」——完全重合是 1.0，完全不相交是 0.0。

```gdscript
## 把一张精灵的不透明像素取成一个位图
func _sprite_mask(sprite_id: StringName) -> Dictionary:
    var texture: Texture2D = PixelArt.get_texture(sprite_id)
    var image: Image = texture.get_image()
    var w: int = image.get_width()
    var h: int = image.get_height()
    var bits: PackedByteArray = PackedByteArray()
    bits.resize(w * h)
    for y: int in h:
        for x: int in w:
            bits[y * w + x] = 1 if image.get_pixel(x, y).a > 0.5 else 0
    return {"w": w, "h": h, "pivot": PixelArt.get_pivot(sprite_id), "bits": bits}
```

**关键点：直接读真实贴图的像素，而不是重新解析一遍字符画。** 这样测的就是「玩家眼睛真正看到的东西」——字符画改了、透明度变了、贴图替换了，都会反映出来。

比较时按**锚点（脚底中心）**对齐：

```gdscript
func _mask_iou(a: Dictionary, b: Dictionary) -> float:
    # 以脚底中心为原点，遍历两张图并集的范围
    var min_x: int = mini(-int(ap.x), -int(bp.x))
    var max_x: int = maxi(aw - int(ap.x), bw - int(bp.x))
    # ... 逐像素判断 in_a / in_b，累计交集和并集
    return 0.0 if union == 0 else float(intersection) / float(union)
```

## 三次把指标做错

这三条比指标本身更值得看，因为**它们全是「指标看起来在工作、实际已经失去分辨能力」的情形。**

### 错误一：只比较 sprite_id

第一版的做法很自然：检查有没有两个敌人用了同一个 `sprite_id`。

然后我给血尸画了一张**新图**，ID 就不同了，检查通过。

但那张新图是「方肩 + 双臂外张」的造型——**和黑僵的轮廓撞在一起**：

```
血尸 vs 黑僵     0.835     ← 比「跳尸 vs 黑僵」的 0.744 还高
```

而这两个敌人的应对方式**完全相反**：一个要在远处打死（它死后会炸），一个要集中火力硬啃。认错代价很大。

**教训：给一种敌人换一张新图太容易了，容易到你会在没改变轮廓的情况下换掉它。必须比较像素，不能比较 ID。**

修法是把血尸重新设计成**一整个圆鼓鼓的球**——没有肩膀、没有手臂、顶上一颗陷进去的小头、底下一对短腿。轮廓从「人形」变成「球」之后：

```
血尸 vs 黑僵     0.835  →  0.700
```

它成了全场唯一没有肩膀的东西。

### 错误二：先把两张图归一化到同一尺寸

一开始我觉得「对齐尺寸再比较更公平」，于是把每张剪影按包围盒拉伸成统一的 20x20 网格。

结果所有「人形」敌人的相似度都挤在 **0.78 ~ 0.83** 之间——指标彻底失去分辨能力。

原因是归一化把**长宽比和相对大小**一起抹掉了，而这两样恰恰是玩家唯一来得及比较的东西：

- 飞尸是**横躺着的**（20x9）
- 跳尸是**竖着的**（16x16）
- 棺中客躺下时是**扁的**（贴图压在下半部）

如果先把它们各自拉伸到同一尺寸，这些差别全都没了。

**正确做法是不做任何归一化，按原生尺度、锚点对齐后直接叠加。** 这样长宽比和相对大小都被保留下来。

改回原生尺度之后，指标立刻有了分辨能力——相似度从 0.10 到 0.83 铺开：

```
最不像的一对：0.101   （血尸 vs 飞尸）
最像的一对：  0.835   （血尸 vs 黑僵，就是上面那个问题）
```

### 错误三：两个 Boss 相似度 1.00

修完血尸之后，测试又报了一条：

```
尸王 和 旱魃（剪影相似度 1.00，超过 0.78）
```

它们用了同一张跳尸的贴图。

**两个 Boss 长得一样，比两个杂兵长得像更糟**——Boss 是玩家一整局的高潮时刻。玩家花了 5 分钟走到那里，结果第二个 Boss 和第一个长得一模一样，那种"我打过这个"的感觉会立刻冒出来。

修法是把它们做成**相反的形状**：

- **尸王**：矮胖 + 顶部极宽（清朝官服配展翅官帽，帽檐比肩膀还宽）
- **旱魃**：瘦长 + 顶部炸开（民俗里的干旱之鬼，光头、头顶一簇火苗）

一个横一个竖，相似度从 1.00 降到 0.603。

## 阈值怎么标定

阈值不能拍脑袋，要看实测分布。这个项目的做法是：

| 情形 | 相似度 |
| --- | --- |
| 血尸 vs 黑僵（**改造前，有问题**） | 0.835 |
| 跳尸 vs 黑僵（机制相同，允许像） | 0.744 |
| 跳尸 vs 血尸（改造后最像的一对） | 0.741 |
| 血尸 vs 黑僵（改造后） | 0.700 |
| 尸王 vs 旱魃（改造后） | 0.603 |

阈值取 **0.78**：它在「有问题」的 0.835 和「可接受」的 0.741 之间，两边都留了余量。

另外还有两个豁免规则：

- **机制等价的敌人跳过**（上面的 `_same_threat_profile`）
- **体型差 1.8 倍以上的跳过**（比如 Boss 对杂兵，玩家一眼就能分开）

## 顺带做的工具：敌人图鉴

自动化测试能守住「不许太像」，但它守不住「够不够好认」。这件事需要人来看。

所以做了一个专门的截图镜头：**把所有敌人按出场顺序排成一张静态参考表，每个都带名字。**

```
第一行（0~75 秒）：  纸人   跳尸   飞尸   鬼火   女鬼
第二行（100~140 秒）：纸扎童 血尸  镜中鬼 黑僵
第三行（150~160 秒）：棺中客(躺着) 棺中客(起身) 养尸人
第四行：             尸王   旱魃
```

三条摆放规则：

1. **按出场时间排序，而不是按强度。** 这样这张图同时就是难度曲线图——从左到右、从上到下，就是玩家在一局里遇到它们的顺序。
2. **加名字。** 没有名字的表只能看「长得像不像」；有名字才能对照设计文档检查「该像的像了没有、该不像的区分开了没有」。
3. **有多个形态的敌人要全放。** 棺中客故意放了两个（躺着的棺材 + 起身的立绘），因为只画一个的话这张参考表就漏掉了它的重点——而且两者并排才看得出玩家能不能一眼分辨。

摆完之后**暂停整棵树**，让所有敌人停在原地。不暂停的话它们会朝玩家（画面正下方）走过来，几秒钟就把这张表挤成一团。

**为什么必须"静态" + "并排"**：动态场面里你的眼睛永远在追玩家，根本不会去比较敌人之间的差别。只有摆成一张静止的表，你才会突然发现「这两个我居然分不出来」。

## 改造前后的完整对比

| 敌人对 | 改造前 | 改造后 |
| --- | --- | --- |
| 血尸 vs 黑僵 | **0.835** | 0.700 |
| 尸王 vs 旱魃 | **1.000** | 0.603 |

改造涉及 5 张新精灵：

| 精灵 | 造型要点 |
| --- | --- |
| 血尸 | 圆球状，**没有肩膀**，顶上一颗陷进去的小头 |
| 养尸人 | 兜帽长袍 + 一根**高出头顶**的招魂幡（它必须是全场最高的东西） |
| 黑僵 | 方肩甲胄 + 宽檐官帽，比跳尸更宽更壮 |
| 飞尸 | **整个身体横过来**飞，双臂前伸，身后拖着破烂衣摆 |
| 尸王 / 旱魃 | 矮胖宽帽檐 / 瘦长火苗头，一横一竖 |

改完之后，所有 13 种敌人的相似度全部低于 0.78 阈值（最高的 0.744 是「本该像」的跳尸 vs 黑僵）。

## 可辨识度其实有四个维度

这篇文章主要讲剪影，但完整的可辨识度还包括：

| 维度 | 什么时候管用 | 这个项目的做法 |
| --- | --- | --- |
| **轮廓** | 最可靠，混战中首选 | 本文的 IOU 测试 |
| **相对大小** | 中等距离有效 | Boss 是杂兵的 2.6~3.1 倍 |
| **配色** | 近距离有效 | 友方（鬼仆）用青色，敌人里没有这个色系 |
| **动作** | 只对"会动的"有效 | 飞尸是横着飞的，镜中鬼是**上下颠倒**的 |

**「动作」这个维度很省力但常被忽略**：镜中鬼的设计就是「整个上下颠倒的鬼」——脚在上、头在下。倒影是最直观的视觉语言，玩家不需要读任何文字就明白这个敌人不一样。

不过要注意：动作只能在它进入视野之后才起作用，而**剪影在你第一次看到它的那一瞬间就起作用了**。所以轮廓永远是第一优先。

## 新手怎么用这套东西

如果你在做自己的游戏，建议这个顺序：

1. **先人工检查一遍。** 把所有敌人并排放在一张静态画面里，缩小到实际游戏里的尺寸，然后问自己「我能在半秒内分辨出每一个吗」。
2. **写一条最粗的规则。** 哪怕只是「不许有两个敌人用同一张精灵」也比没有强。
3. **升级到像素级比较。** 规则写成「机制不同的敌人，剪影 IOU 不能超过某个阈值」。
4. **阈值用你自己的数据标定。** 先测出所有敌人对的相似度分布，看「明显有问题的那几对」落在什么区间，阈值定在它和正常区之间。
5. **把图鉴做成一个可以随时重跑的工具。** 加一个新敌人就重跑一次——**这类问题的特点是，你每加一个新敌人都有可能重新引入它。**

最后一条尤其重要。这个项目在加「镜中鬼」和「棺中客」的时候，就分别又跑了一次相似度检查，确认新精灵没有和已有敌人撞车。

**一个只检查过一次的美术规则，等于没有规则。**
